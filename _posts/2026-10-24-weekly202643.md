## Python

- [Parsing JSON at tens of gigabytes per second… in Python](https://lemire.me/blog/2026/10/12/parsing-json-at-tens-of-gigabytes-per-second-in-python/)
    - 이 기사는 파이썬 환경에서 초당 수십 기가바이트에 달하는 속도로 대용량 JSON 데이터를 파싱하는 기법과 벤치마크 결과를 다룹니다.
    - SIMD 명령어를 활용해 단일 코어에서도 기가바이트급 처리량을 내는 `simdjson`의 파이썬 바인딩(`fastsimdjson`)과 GIL이 제거된 자유 스레딩(free-threaded) 파이썬을 결합하여, 수 기가바이트 규모의 NDJSON 아카이브를 다수의 CPU 코어에 선형적으로 분산해 순식간에 처리하는 과정을 설명합니다.

- [PyTorch Year in Review: OpenTeams' Contributions in 2026](https://openteams.com/engineering-blog/pytorch-year-in-review-2026/)
    - 이 기사는 2026년 한 해 동안 급격히 변화한 PyTorch 생태계의 흐름과 OpenTeams 엔지니어링 팀이 기여한 핵심 기술적 성과를 돌아보는 글입니다.
    - AI 코딩 에이전트의 확산으로 풀 리퀘스트가 58% 급증함에 따라 도입된 AI 친화적 개발 정책(RFC-0058) 등 프로젝트 운영상의 변화와 함께, `torch.compile` 내부 심볼릭 인터프리터의 CPython 호환성 재설계, 파이썬 3.15 컴파일러 즉시 지원, 빌드 백엔드 전면 개편 같은 주요 엔지니어링 작업을 소개합니다.

## JS/TS/FP

- [JPEG XL vs AVIF for web use-cases](https://jakearchibald.com/2026/jpeg-xl-vs-avif/)
    - 이 기사는 주요 웹 브라우저 전반에 JPEG XL 지원이 도입된 시점에서 웹 환경의 다양한 사용 사례를 기준으로 JPEG XL과 AVIF의 성능과 압축 효율을 정밀하게 비교한 글입니다.
    - 일반 사진과 스크린샷, 일러스트, 투명도, HDR 이미지를 대상으로 `avifenc`, `libjxl`, `jixel` 인코더를 테스트한 결과, 무손실 압축이나 레거시 JPEG 재압축 및 일부 HDR 영역에서는 JPEG XL이 강점을 보이지만, 일반적인 손실 압축 웹 이미지에서는 파일 크기와 디코딩 속도 면에서 여전히 AVIF가 더 나은 기본 선택지라고 설명합니다.

- [GraphQL as a foundation for malleable UI](https://jovidecroock.com/blog/graphql-malleable-ui/)
    - 이 기사는 애플리케이션 실행 중에 AI 에이전트가 사용자의 요구에 맞춰 화면 구조를 동적으로 변형하는 유연한 UI(malleable UI) 환경에서 GraphQL이 왜 이상적인 데이터 계층이 되는지 설명합니다.
    - 예컨대 상품 카드 그리드를 창고별 재고 비교 표로 즉시 바꿀 때 고정된 REST 엔드포인트는 데이터 부족이나 과잉 패칭 문제를 겪는 반면, GraphQL은 타입이 정의된 스키마와 시맨틱 인트로스펙션을 통해 에이전트가 변경된 UI에 꼭 필요한 데이터 쿼리를 안전하고 정확하게 즉석에서 조합할 수 있다고 강조합니다.
