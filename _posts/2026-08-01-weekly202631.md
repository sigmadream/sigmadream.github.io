## Python

- [In-House LLM Serving at Netflix](https://netflixtechblog.com/in-house-llm-serving-at-netflix-a5a8e799ea2c)
    - 이 기사는 넷플릭스가 외부 호스팅 API에만 의존하지 않고 자체적인 프로덕션급 LLM 서빙 플랫폼을 어떻게 구축했는지 다루는 글입니다.
    - 기존 ML 인프라에 vLLM과 NVIDIA Triton Inference Server를 통합해 OpenAI 호환 HTTP API와 gRPC를 제공하는 아키텍처와 함께, 고부하 환경에서의 병목 해결, 프리필 및 상태 관리, 무중단 배포 같은 실무 엔지니어링 과제를 어떻게 풀어냈는지 설명합니다.

- [How To Train a Generative Kick Drum Model on Your Old Linux Desktop With 6GB of VRAM](https://www.zhinit.dev/blog/training-a-kick-drum-diffusion-model)
    - 이 기사는 6GB VRAM을 가진 구형 리눅스 데스크톱(GTX 1660 SUPER)에서 킥 드럼 사운드를 생성하는 잠재 확산 모델을 직접 학습시키고 배포한 과정을 다룹니다.
    - 13,000개 이상의 샘플 데이터를 바탕으로 오디오 스펙트로그램을 압축하는 VAE, 노이즈를 제거하는 Diffusion U-Net, 오디오 파형을 복원하는 HiFi-GAN 보코더까지 3단계 파이프라인을 제한된 GPU 메모리에 맞춰 설계하고 학습시킨 실전 경험을 정리한 글입니다.

- [Django Form Templates](https://www.better-simple.com/django/2026/07/22/nifty-feature-form-templates/)
    - 이 기사는 Django에 내장된 폼 및 필드 템플릿 기능을 활용해 폼 레이아웃과 렌더링 구조를 깔끔하게 커스터마이징하는 방법을 설명합니다.
    - 페이지 템플릿 안에서 복잡한 필드 반복문이나 에러 처리를 일일이 작성하거나 무거운 서드파티 패키지를 도입하는 대신, 폼 수준과 개별 필드 수준의 재사용 가능한 템플릿을 분리해 마크업을 유연하게 제어하는 실용적인 팁을 소개합니다.

## JS/TS/FP

- [Rust Is Eating JavaScript](https://leerob.com/rust)
    - 이 기사는 웹 애플리케이션 작성 언어로서 자바스크립트의 위치는 유지되면서도, 자바스크립트 생태계를 지탱하는 빌드 및 개발 도구들이 빠르게 Rust로 대체되고 있는 흐름을 다룹니다.
    - 단일 스레드 기반 자바스크립트 도구들이 대규모 코드베이스에서 겪는 성능 한계를 지적하며, SWC, Turbopack, Biome 같은 Rust 기반 도구들이 napi-rs 등을 통해 기존 npm 워크플로우 안에 자연스럽게 녹아들어 컴파일과 번들링, 린팅 속도를 크게 끌어올리는 과정을 설명합니다.

- [The Absolute State of Management](https://infrequently.org/2026/07/state-management/)
    - 이 기사는 프론트엔드 생태계, 특히 React 시대에 굳어진 상태 관리(state management)라는 용어와 관련 도구들의 실상을 비판적으로 살피는 글입니다.
    - 저자는 대다수의 상태 관리 도구가 실제로는 상태를 관리하는 것이 아니라 단순히 전파(propagation)할 뿐이라고 지적하며, 진정한 상태 관리 도구라면 시간이라는 차원과 상태 충돌을 다루는 명확한 패턴을 갖추어야 한다고 주장합니다.

- [Each test should own its setup](https://ryanzidago.com/posts/self-contained-tests-in-elixir/)
    - 이 기사는 Elixir의 ExUnit 등에서 흔히 쓰는 공통 setup 블록에 과도하게 의존하기보다, 각 테스트가 자신에게 필요한 설정을 직접 소유하는 자기 완결적 테스트를 작성해야 한다고 주장합니다.
    - 코드 줄 수를 줄이려고 테스트 데이터를 setup 콜백으로 숨기면 테스트의 맥락을 파악하기 위해 코드를 오가야 하고 상태가 취약해지므로, 지역성과 가독성을 우선해 각 테스트 본문 안에서 필요한 상태를 명시적으로 구성하는 편이 유지보수에 유리하다고 설명합니다.
