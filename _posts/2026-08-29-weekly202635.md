## Python

- [From P-Code to GNN: extract binary code semantics](https://blog.quarkslab.com/from-p-code-to-gnn-extract-binary-code-semantics.html)
    - 이 기사는 Ghidra의 중간 표현인 P-Code와 그래프 신경망(GNN)을 결합해 바이너리 코드의 의미를 추출하고 분석하는 방법을 다룹니다.
    - CPU 아키텍처에 종속적인 어셈블리어 대신 P-Code를 사용해 바이너리 함수를 데이터 흐름 및 제어 흐름 그래프로 변환하는 오픈소스 파이썬 라이브러리 `pcode_graph`를 소개하고, 이를 바탕으로 서로 다른 컴파일러나 최적화 옵션으로 빌드된 바이너리 간 함수 유사도를 탐지하는 머신러닝 파이프라인을 설명합니다.

- [When str.lower() is a security vulnerability in Python](https://sethmlarson.dev/when-str-lower-is-a-security-vulnerability)
    - 이 기사는 파이썬에서 흔히 사용하는 `str.lower()` 같은 대소문자 변환 메서드가 유니코드 버전 차이나 파서 불일치와 맞물릴 때 어떻게 보안 취약점으로 이어질 수 있는지 설명합니다.
    - 국제화 도메인 이름(IDN)이나 StringPrep 등을 처리할 때 보안 필터 계층의 문자열 정규화 결과와 실제 요청을 처리하는 하위 네트워크 계층의 해석이 달라지면, 허용 목록 우회나 도메인 혼동, SSRF 같은 공격에 노출될 수 있음을 짚어냅니다.

- [The Polars vs SQL differences nobody is talking about](https://labs.quansight.org/blog/polars-vs-sql-differences)
    - 이 기사는 흔히 다루어지는 속도 벤치마크 대신, Polars와 SQL 사이에 존재하는 근본적인 의미론적 차이와 멘탈 모델의 차이를 집중적으로 비교합니다.
    - 행의 순서가 엄격히 보존되는 열 중심 구조의 Polars와 순서가 정의되지 않은 행의 집합을 다루는 관계형 모델 기반 SQL의 차이를 설명하고, 리터럴(`pl.lit`) 평가 방식이나 윈도우 함수 및 집계 표현식을 조합할 때의 문법적 유연성이 어떻게 다른지 예제로 보여줍니다.

## JS/TS/FP

- [Bun 1.4](https://bun.com/blog/bun-v1.4)
    - 이 기사는 런타임 내부 코드베이스를 Zig에서 Rust로 전환하고 다수의 내장 API와 성능 개선을 담아 출시된 Bun 1.4의 주요 변경 사항을 소개합니다.
    - `Bun.WebView`, `Bun.Image`, `Bun.markdown`, `Bun.cron`, `Bun.Terminal` 같은 네이티브 도구 모음을 기본 탑재하고, 최적화된 `mimalloc` 메모리 할당자 도입과 글로벌 가상 스토어를 통해 메모리 사용량과 콜드 스타트 시간을 줄이는 동시에 Node.js 호환성을 대폭 확대한 내용을 다룹니다.

- [3 Next.js memory leaks measured in production: yours?](https://xabierlameiro.com/blog/nextjs/nextjs-memory-leak-in-production)
    - 이 기사는 자체 호스팅된 프로덕션 환경에서 OOM 종료를 유발했던 Next.js 프레임워크 내부(15.5~16.2 버전)의 세 가지 메모리 누수 원인을 측정하고 추적한 과정을 다룹니다.
    - 라우터 LRU 캐시가 URL 키 크기를 계산하지 않아 발생한 누수, 클라이언트 연결 중단 시 RSC 렌더 트리가 메모리에 남는 문제, 미들웨어 샌드박스의 `setTimeout` ID가 해제되지 않는 문제를 각각 힙 스냅샷과 메모리 곡선 분석으로 규명하고, 이를 자동 점검하는 `next-leak` CLI 도구와 Next.js 16.3.0의 수정 내역을 함께 정리합니다.
